# Команда ИИ-агентов собственника TSG — этапы 1–2

Что внутри:
- **main.py** — точка входа для Railway: `APP=bot` запускает бота, без неё — MCP-сервер.
- **tsg_bitrix/** — MCP-сервер «tsg-bitrix» для Railway. Только чтение Битрикса. У каждого агента свой адрес (`/<роль>/mcp`) и свой токен; поля с деньгами и персональными данными вырезаются на сервере по матрице доступа (`tsg_bitrix/policy.py`).
- **agents/** — промпты: Тимлид, Производство, Аккаунт, Бухгалтер + общие правила.
- **scripts/setup_agents.py** — создаёт в Claude Platform среду, хранилище токенов и агентов; повторный запуск обновляет их.
- **owner_bot/** — Telegram-бот собственника: голос или текст → Тимлид → ответ. Отдельный сервис Railway.
- **scripts/ask.py** — вопрос Тимлиду из терминала и вечерняя сводка (`--summary`).
- **tests/** — проверка прав без доступа к реальному Битриксу.

## Запуск — по шагам

### 1. Вебхук Битрикса (только чтение по смыслу, права — на портале)
Битрикс → Разработчикам → Другое → Входящий вебхук. Права: **CRM, Задачи, Пользователи, Структура компании**.
Создайте его под своей учёткой (239). Сервер всё равно вызывает только методы чтения — остальные отклоняются до отправки.

### 2. Сервер на Railway
1. В проекте Railway: + Create → GitHub Repo → этот репозиторий. Railway сам запустит `python main.py`; без переменной `APP` стартует MCP-сервер. (Config-as-code Railway больше не подключает новым сервисам, поэтому файлов railway.json здесь нет.)
2. Variables:
   - `BITRIX_WEBHOOK_URL` — адрес вебхука из шага 1;
   - `MCP_TOKEN_TEAMLEAD`, `MCP_TOKEN_PRODUCTION`, `MCP_TOKEN_ACCOUNT`, `MCP_TOKEN_ACCOUNTANT` — сгенерируйте `python scripts/make_tokens.py`.
3. Settings → Networking → Generate Domain. Проверка: `https://<домен>/health` отвечает `ok`.
4. В логах Railway — журнал: каждая строка = роль, инструмент, параметры, сколько записей отдано.

### 3. Проверить, что агенты увидят в Битриксе
```
BITRIX_WEBHOOK_URL=... python scripts/inspect_fields.py
```
Для каждого поля покажет: `money` / `pii` / `plain` и какие роли его видят. ЗП, ФОТ, ОФ / НЕ ОФ должны быть `money`, ИИН и карты — `pii`. Если поле определилось неверно — переменная `FIELD_OVERRIDES` на Railway.

### 4. Агенты в Claude Platform
```
pip install -r requirements.txt
export ANTHROPIC_API_KEY=...        # Console → Ключи API
export MCP_BASE_URL=https://<домен Railway>
export MCP_TOKEN_TEAMLEAD=... MCP_TOKEN_PRODUCTION=... MCP_TOKEN_ACCOUNT=... MCP_TOKEN_ACCOUNTANT=...
python scripts/setup_agents.py
```
После этого в Console → Управляемые агенты → Агенты появятся «TSG · Тимлид» и три специалиста. ID записаны в `state.json` (секретов там нет). Промпт поменяли — запустите скрипт ещё раз.

### 5. Первая проверка
```
python scripts/ask.py "Сколько объектов в Битриксе по Алматы и Астане?"
python scripts/ask.py --summary
```
Сессию и все вызовы агентов видно в Console → Сессии. Лимит расходов на сессию — `SESSION_BUDGET_CENTS` (по умолчанию 200 = 2 $).

### 6. Telegram-бот (этап 3)
1. В Telegram: @BotFather → `/newbot` → получите токен. Свой Telegram ID узнайте у @userinfobot.
2. Распознавание голосовых — Groq (Whisper large-v3), тот же сервис, что у HR-бота: ключ в console.groq.com → API Keys, переменная `GROQ_API_KEY`. Можно взять тот же ключ, что у HR-бота, но лучше отдельный — тогда расходы и лимиты не смешиваются. Запасные варианты: `STT_PROVIDER=openai` или `yandex`.
3. В том же проекте Railway — второй сервис из этого же репозитория (+ Create → GitHub Repo). В Variables добавьте `APP=bot` — по этой переменной тот же код запускает бота, а не MCP-сервер. Домен ему не нужен: бот сам забирает сообщения у Telegram.
4. Variables второго сервиса: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_IDS` (ваш ID), `ANTHROPIC_API_KEY`, `GROQ_API_KEY`, и три строки, которые напечатал `setup_agents.py`: `TEAMLEAD_AGENT_ID`, `AGENTS_ENVIRONMENT_ID`, `AGENTS_VAULT_ID`. Для вечерней сводки — `SUMMARY_TIME=19:00`.
5. Напишите боту `/start`. Появятся кнопки «Сводка за сегодня», «Что горит», «Новая тема».

Как ведёт себя бот:
- Отвечает только ID из `TELEGRAM_ALLOWED_IDS`; остальным молчит, попытка пишется в лог.
- Голосовое → показывает распознанный текст («🎙 «…»») → «Принял, собираю…» → по ходу пишет, какие агенты подключились → ответ.
- Одна сессия Тимлида на чат и на день: в течение дня он помнит разговор, утром начинает заново. «Новая тема» — сбросить раньше.
- `/voice` — включает ответ голосом после текстового. Для этого нужен ещё `OPENAI_API_KEY` (синтез речи OpenAI); без него бот отвечает только текстом.
- Каждый вопрос и ответ пишется в лог Railway с Telegram ID.

## Права в этой версии
| Роль | Разделы | Деньги | Задачи |
|---|---|---|---|
| Тимлид | Объекты, сотрудники, подразделения | нет | да |
| Производство | Объекты, Смены, Обращения, NPS, Аудиты | нет | да |
| Аккаунт | + Договоры | да (решение 14.10.2026) | да |
| Бухгалтер | Объекты, Смены, Договоры, Бухгалтерия | да | нет |

Никто из агентов не получает ИИН, документы и банковские реквизиты. Запись в Битрикс отсутствует в коде полностью — появится на этапе 5 отдельным ключом кабинета.
